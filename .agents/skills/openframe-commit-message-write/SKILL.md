# OpenFrame 제품 커밋 메시지 작성

## 적용 범위

- 이 형식은 OpenFrame 제품 소스 저장소의 커밋 및 해당 제품 변경에 대한 커밋 메시지 초안에만 적용한다.
- Codex 에이전트의 AGENTS.md·스킬·템플릿을 관리하는 저장소의 커밋에는 적용하지 않는다. 그런 변경은 해당 저장소의 기존 일반 커밋 관례를 따른다.
- 적용 여부는 메시지가 설명하는 대상 저장소와 변경 내용으로 판단한다. 현재 작업 디렉터리, Jira 이슈 ID, 초안이 저장되는 위치만으로 제품 커밋이라고 판단하지 않는다. 지침 저장소에 저장하는 제품 코드의 커밋 초안은 제품 형식을 적용하되, 그 초안 파일 자체를 지침 저장소에 커밋할 때는 해당 저장소 관례를 따른다.

## 근거 확인

- 대상 저장소의 `git status`, 관련 `git diff`, 최근 커밋 제목을 읽어 실제 변경 범위와 제목 관례를 확인한다. staging된 내용을 커밋하는 요청이면 `git diff --cached`를 기준으로 한다. 미추적 파일은 요청 범위에 속하는 내용만 확인한다.
- 본문은 최근 커밋의 형식이 혼재하더라도 아래 `artifact → version → details` 순서로 작성한다. 사용자가 이번 요청에 다른 형식을 명시하면 그 지시를 우선한다.
- 변경한 모듈의 저장소 상대 경로와 해당 모듈의 실제 버전을 소스 트리·Makefile·버전 소스·빌드 결과에서 확인한다. 기존 조사에서 확보한 현재 근거가 충분하면 같은 조회·빌드를 반복하지 않는다.
- 메시지 작성은 staging·커밋·push·버전 증가 권한을 포함하지 않는다. 실제 Git 변경 권한과 환경 진입 절차는 [루트 AGENTS.md](../../../AGENTS.md)를 따른다.

## 제목과 본문

제목은 저장소 관례에 맞춰 이슈 ID, 변경 유형, 핵심 변경을 한 줄로 적는다. 이슈 ID가 없으면 만들지 않는다. 제목과 본문 사이에 빈 줄을 두고, 본문 필드는 다음 표기와 순서를 유지한다.

```text
<이슈 ID>:<변경 유형> <핵심 변경>

* artifact: <src를 제외한 저장소 상대 모듈 경로>
* version: <해당 모듈의 실제 버전>
* details:
    - <문제 조건과 변경 후 동작>
    - <추가 변경 또는 필요한 영향 범위>
    - <실행한 검증과 결과·미검증 범위, 필요한 경우>
```

꺾쇠 자리표시자는 실제 값으로 바꾼다. 제목의 변경 유형 꺾쇠 표기는 대상 저장소가 사용하는 형식에 맞춘다.

| 필드 | 작성 기준 |
| --- | --- |
| `artifact` | 변경한 모듈의 저장소 루트 상대 디렉터리 경로를 적고, 경로 구성요소 중 `src`를 제외한다. 구분자는 `/`를 사용한다. 예: `<제품>/src/<모듈 경로>` → `<제품>/<모듈 경로>`. 실행파일·라이브러리 이름만 적거나 로컬 절대 경로를 쓰지 않는다. 여러 모듈이면 해당 경로를 쉼표로 구분한다. 테스트·문서만 변경했으면 실제 대상 디렉터리 경로를 같은 기준으로 적는다. |
| `version` | 산출물의 전체 버전 표기를 확인해 적는다. 제품 프로필의 주·부 버전이나 YAML 스키마 버전을 대신 쓰지 않는다. 여러 산출물의 버전이 다르면 각 산출물과 버전을 대응시킨다. 확인되지 않았으면 `미확인`, 독립 버전이 없는 대상이면 `해당 없음`으로 명시하고 추측하거나 버전을 올리지 않는다. |
| `details` | 실제 diff의 변경 목적·조건·결과를 들여쓴 `-` 항목으로 적는다. 파일 목록이나 구현 경과를 나열하기보다 변경 동작을 설명한다. 필요한 검증은 같은 필드 안에 요약하며 실행 범위·결과와 미실행을 구분한다. |

## 산출물과 검토

- Jira 이슈 산출물 경로와 기록 시점은 [common-issue-artifacts](../common-issue-artifacts/SKILL.md)를 따른다. 그 스킬이 정한 `commit-message.md`에는 복사 가능한 커밋 메시지만 저장하고 초안·미커밋 상태 설명은 구현 보고나 최종 답변에 둔다.
- 세 필드가 모두 존재하는지, artifact가 실제 변경 모듈의 경로이며 `src`가 제외되었는지, 버전의 근거가 있는지, details가 실제 변경 및 검증 범위와 일치하는지 확인한다. 실패·skip·미실행을 통과로 적지 않는다.
- 비밀번호·토큰·접속 비밀값은 넣지 않는다. 스킬과 재사용 예시에는 세션별 값이나 비공개 소스·식별명·알고리즘을 옮기지 않고 루트의 공개 정보 범위를 따른다.
